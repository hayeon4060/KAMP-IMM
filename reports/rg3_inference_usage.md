# RG3 추론 코드 및 모델 사용 안내

## 제공 상태

가스 저장 모델 추론은 구현되어 있다. 최고 미성형 후보143의 학습 소스133/139/141도 별도 작업 폴더에서 찾아 기존 연결 코드와 함께 추가했다. 기존 연결의 실행은157번과 `rg3_existing_pipeline_reproduction.md`를 참고한다. 다만155번의 저장 가중치 기반 API는 여전히 가스 전용이므로 **이 경로의 가스 음성은 정상 확정이 아니며 `미성형 모델 미연결`로 출력**한다. 다른 미성형 모델로 임의 대체하지 않았다.

사용자의 노트북 우선 요청에 따라 실행 소스는 ipynb로 제공한다. `rg3_gas.py`, `rg3_shortshot.py`라는 이름의 미구현 파일이 있다고 가정하지 않는다.

## 파일 역할

- `notebooks/154_rg3_gas_model_export.ipynb`: 첫 코드 셀은 피처 생성·모델 저장/읽기·가스 추론·cascade 인터페이스 정의. 두 번째 코드 셀만 기존 정상566/가스17로 학습해 가중치를 저장한다. 마지막 셀은 개발자의 원본 자료로 예제 파일을 만드는 선택 단계이며 일반 추론에는 실행할 필요가 없다.
- `models/rg3_gas_final_fit.joblib` 및 `.json`: 학습한 가스 모델·정상 관계회귀·조건부 정상 참조·고정 임계값. 추론 시 재학습하지 않는다. SHA256 및 sklearn 버전을 확인하고 읽는다.
- `notebooks/155_rg3_new_data_inference.ipynb`: 새 CSV → 과거 피처 → 저장 모델 추론 → 결과 CSV. 154번의 정의 셀만 읽고 학습 셀은 실행하지 않는다.
- `notebooks/156_rg3_inference_selfcheck.ipynb`: 동봉한 작은 실제 입력 예제로 무학습 추론, 입력 정답 불변성, 배치 불변성, 이력 부족/다른 설비 판정보류와 cascade 인터페이스 라우팅 확인. 정답 성능 독립검증을 의미하지 않는다.

전체 비라벨29,236 Shot을 대상으로도 이전 적용본287개와 일치하는지 별도로 검증했다. 그 기록은 `reports/tables/rg3_inference_selfcheck.json`에 남겼다. 156번의 휴대 가능한 검증은 대용량 비라벨 파일이나 평가 예측 CSV 없이 실행된다.

## 실행

기존 `.venv`를 활성화하고 `requirements.txt` 환경을 사용한다. 155번은 기본적으로 `examples/rg3_gas_raw_input.csv`(5 Shot)와 `examples/rg3_gas_raw_history.csv`(133행)를 사용해 바로 실행할 수 있다. 새 자료에는 `INPUT_CSV`, 필요하면 `CONTEXT_CSV`, `OUTPUT_CSV`를 지정한다. 모델 파일은 동봉하므로 154번 전체를 재학습할 필요가 없다. 동봉 예제는 가스 정답5개가 아니라 가스 후보로 판정된 실제 센서 입력5개다.

모델을 다시 내보낼 때 사용하는 고정 경계는 `reports/tables/rg3_unlabeled_gas_frozen_thresholds.csv`에 동봉했다. 이 값은 기존 라벨 OOF 정상 점수로 정한 값이지 비라벨의 상위1%를 선택한 값이 아니다.

새 입력은 **원본 비표준화 센서 단위**로 제공해야 한다. 필수 메타데이터는 `EQUIP_CD`, `TimeStamp`, `product`(또는 CN7/RG3를 포함한 `PART_NAME`)다. 24개 센서명은 154번 `RAW`에 명시되어 있다. PassOrFail/Reason은 필요 없으며 제공되어도 피처 생성에서 버린다. 예측 결과 CSV나 평가 정답 CSV를 추론 입력으로 쓰지 않는다.

이전 설비 기록을 `CONTEXT_CSV`로 제공하면 product 전환 또는30분 초과 공백에서 이력을 재시작한다. 각 Shot은 현재보다 이전 기록 최대10개로 표준편차·중앙값 편차를 구한다(최소5개). 같은 설비의 다른 제품 기록도 있으면 포함해야 제품 전환 경계가 반영된다. Timestamp 없는 데이터나 표준화된 대회 센서값은 이 원본 모델에 그대로 넣을 수 없다.

동일 설비·제품·Timestamp는 한 Shot으로 통합한다. 센서 충돌, 모호한 제품, 필요한 센서/이력 부족, 학습하지 않은 설비는 판정보류한다. 지원 범위는 S14/RG3다. 이력 부족을 정상으로 강제하지 않는다.

## 함수 연결

팀 코드에서는 154번의 첫 코드 셀을 `nbformat`으로 읽어 정의만 로드한 후 `load_bundle(model_path)`, `prepare_features(query_raw, context_raw)`, `predict_cascade(bundle, features)` 순서로 호출할 수 있다. 이 함수 호출은 학습 데이터 경로를 참조하지 않는다.

향후 미성형을 별도 저장 가중치 API로 분리할 경우 `predict_cascade(..., shortshot_predictor=...)`에 실제 학습된 미성형 모델을 연결한다. 가스 음성으로 분기된 Shot만 미성형 모델에 보내며, 가스 제거 후 센서 이력 창을 다시 계산하지 않는다. 실제 정답으로 분기하지 않는다. 현재 기존 연결 실행은157번에서 이미 제공된다.

## 성능 해석과 보안

이 모델은 기존8TP/6FP 탐색 후보의 구조·피처를 전체 정상566/가스17에 최종 학습한 적용본이다. 이전 구간별 교차검증 가중치와 같은 단일 모델이 아니며, 최종 재학습 모델이 독립 평가에서 F1=0.516을 보장한다고 주장하지 않는다. 비라벨 적용본 일치도 정답 정확도를 입증하지 않는다. 해당 비라벨은 라벨 기간보다 이전 기록에 대한 소급 추론이다.

joblib은 pickle 기반이므로 임의 다운로드 모델을 읽으면 안 된다. 이 저장소에서 직접 생성하고 무결성을 확인한 모델만 읽어야 한다. 저장 모델은 sklearn1.9.1에 맞춰 사용한다.

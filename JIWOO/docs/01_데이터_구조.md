# 데이터 구조 — 읽기 전에 알아야 할 것

## 파일별 성격

| 파일 | 행 | 성격 | 용도 |
|---|---|---|---|
| labeled_data.csv | 7,996 (CN7 3,974 / RG3 1,256, 중복제거 후) | **1차 가공본**. 시각·LH/RH·불량유형 있음, 물리 단위 그대로 | **탐색·진단** |
| unlabeled_data.csv | 795,315 | 1차 가공본. 라벨 없음, 일별 불량수(ERR_FACT_QTY) 있음 | 나중에 약지도용 |
| moldset_labeled_cn7/rg3.csv | 1,211 / 1,182 | **2차 가공본**. 24변수만, 표준화됨 | **모델 학습·제출** |
| moldset_unlabeled_cn7/rg3.csv | 각 3.5만 | 2차 가공본, 라벨 없음 | 준지도용 |

**핵심**: 탐색은 1차, 모델은 2차. 제출 테스트 파일이 2차 형식일 가능성이 높으므로
모델에 LH/RH나 시각을 넣으면 안 된다. 1차에서 알아낸 것을 24변수 안의 파생피처로 옮겨야 한다.

## 반드시 알아야 할 5가지

### 1. 행 2개 = 쇼트 1개
같은 TimeStamp 에 LH, RH 두 행이 있다. 한 번 사출하면 좌우 부품이 하나씩 나오기 때문.
공정값은 쇼트 단위로 기록되므로 두 행의 24변수가 **완전히 동일**하다.
→ 학습/검증을 나눌 때 같은 쇼트는 같은 쪽으로 가야 한다. 안 그러면 누수가 된다.

### 2. CN7은 41%가 완전중복
`drop_duplicates` 를 먼저 해야 한다. `load_labeled()` 가 기본으로 처리한다.

### 3. 불량은 71건, 세 유형
| 유형 | CN7 | RG3 | 성격 |
|---|---|---|---|
| 가스 | 13 | 22 | RG3는 RH에 19/22 집중 → 금형(벤트) 문제로 추정 |
| 초기허용불량 | 10 | 0 | 당일 26~30번째 쇼트에 집중 → 기동 구간 |
| 미성형 | 5 | 10 | 공정 변수로 예측 여지가 있는 유일한 유형 |

### 4. 못 쓰는 변수
- `Switch_Over_Position` : CN7 전부 0, RG3 사실상 0 → 미기록
- `Mold_Temperature_1,2,5~12` : 전부 0 → 센서 미설치
- `Barrel_Temperature_7` : 전부 0

### 5. 이상한 변수 (확인 필요)
- `Average_Screw_RPM` : 29 또는 290 두 값뿐. 평균값이 아니라 상태 플래그로 보임
- `Max_Back_Pressure`(37.9) < `Average_Back_Pressure`(59.5) : 최대가 평균보다 작음. 정의 확인 필요
- `Clamp_Open_Position` : CN7은 648 또는 69.6 두 값. 69.6인 18개 행의 정체 확인 필요

## CN7과 RG3는 다른 공정
| | CN7 | RG3 |
|---|---|---|
| 충전시간 | 4.45초 | 0.94초 |
| 사출속도 | 55.5 | 128.2 |
